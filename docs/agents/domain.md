# 도메인 문서

## 구조

단일 컨텍스트 구조를 사용합니다.

- `CONTEXT.md`: 도메인 개념과 용어
- `docs/adr/`: 설계 결정 기록

## 읽기 규칙

코드 탐색 전에 루트 `CONTEXT.md`와 현재 작업에 관련된 ADR을 읽습니다.
문서가 없으면 그대로 진행하며, 빈 문서를 미리 만들지 않습니다.
용어와 결정을 정리할 필요가 생기면 `domain-modeling` 스킬을 사용합니다.

루트에 `CONTEXT-MAP.md`가 도입되면 맵을 따라 관련 컨텍스트 문서와
해당 컨텍스트의 ADR도 읽습니다.

## 사용 규칙

이슈, 설계 제안, 테스트 이름에는 용어집의 도메인 용어를 사용합니다.
새 개념이 필요하면 기존 용어로 표현할 수 있는지 먼저 확인합니다.
용어집에 실제 공백이 있으면 도메인 모델링 대상으로 기록합니다.
기존 ADR과 충돌하는 제안은 해당 ADR과 충돌 내용을 명시합니다.
